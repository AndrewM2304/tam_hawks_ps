# Studio production

Use for planning, delegating, integrating or resuming work on this game. This is a local repository skill; load it explicitly from `AGENTS.md` and the roster. It is not an unattended task scheduler.

## Load current truth

1. Read `AGENTS.md`, `docs/STATUS.md`, `docs/planning/FIDELITY_TICKETS.md`, `docs/product/AAA_BENCHMARK.md` and `docs/architecture/interfaces.md`.
2. Inspect `git status --short`, current branch and most recent results. Preserve unrelated edits. The owner's main-only instruction supersedes older feature-branch/handoff guidance: work directly on `main`, preserve remote history and push without force. Root alone performs Git integration; specialists do not switch branches or commit a shared checkout.
3. Read `docs/planning/STUDIO.md` and `.agents/agents/README.md`. Load each assigned specialist's skill. Do not assume a logical role has a live worker or that Markdown briefs automatically register runtime agents.

## Plan and dispatch

- Select the earliest useful unblocked ticket. Assign ID, milestone, priority, dependencies, implementation owner, independent BA verifier, paths, public interfaces, acceptance clauses and evidence method. Pending hardware/human review does not halt independent authorised improvements.
- Reconcile current PT24/C01–C11 evidence before choosing a creation task. Native wall/transition/rail contacts, the 78-trick repertoire, compact-map lines and enabled station/train/pond/cable/green/civic content already exist. Preserve them, personal Music isolation, completed diagnostics and rejected cost cells. Extend current proof/capture tools before duplicating infrastructure.
- Parallelise independent investigation and disjoint implementation. Keep shared-file section changes sequential or obtain explicit ownership agreement. Reserve capacity for independent QE and later BA.
- Give each worker a concrete result, not “make it AAA.” Require an early diagnosis, then changes, measured checks, actual inspected frames, known defects and a return report.
- Use original or compatible free licensed assets. Inspect licences separately from code permissions. No purchases, billing, paid APIs, hosted CI, infrastructure or background agent loops. No copied franchise level layouts/branding/assets.

## Integrate and verify

1. Reconcile public contracts and coordinate a source freeze. Run focused checks for changed behaviour, then `./tools/check.sh` for production GDScript. Keep error scans and nonzero failures intact.
2. Capture ordinary-play and diagnostic views with explicit fixture labels and source hashes. Inspect the worst frames and fix reproduced defects; a successful PNG write is not art acceptance.
3. Send independent QE the requirements, candidate source and reproduction commands. Send BA the benchmark clauses and evidence, without requiring them to accept the author summary. Feed defects back to the original owner and retest affected cases.
4. Update the evidence matrix, ticket states and STATUS. “Done” requires all of that ticket's criteria; split a bounded completed implementation from still-open overall fidelity/hardware acceptance.
5. Integrate tested changes directly on `main` using the repository's available remotes/history, without discarding work. Reconcile existing changes by non-force fast-forward/merge where necessary; do not create a feature branch or worktree. Record actual local/remote ref outcomes; never claim a push/merge not performed. Do not trigger hosted CI in this no-spend workflow.

## Handoff

Record current SHA/branch, tested source identity, commands/results, inspected captures, unresolved defect IDs, asset provenance, target-Mac/human gaps and the exact next edit. See `docs/planning/STUDIO.md`. Duration is not an acceptance criterion: do not claim success from hours spent and do not manufacture idle time. Persist on substantive work and leave an honest checkpoint if the session ends before the benchmark is met.
