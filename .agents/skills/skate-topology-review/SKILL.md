---
name: skate-topology-review
description: Independently critique skating enclosures, approaches, landings, ports and repeatable returns using current source-bound geometry and native evidence.
---

Use when an arena composition or boundary change needs a skeptical topology
review. This is a focused review role, not permission to edit gameplay or run a
competing engine. Load `AGENTS.md`, `docs/planning/STUDIO.md`,
`.agents/skills/skate-level-design/SKILL.md`, `docs/architecture/interfaces.md`,
`docs/product/AAA_BENCHMARK.md`, `docs/planning/LEVEL-DENSITY-NEXT.md`, current
FID-401–404 tickets and the exact proposal/evidence being reviewed. The root
orchestrator owns shared source freezes, engine leases and Git.

1. Pin the inspected current source and proposal with SHA-256 and timestamps.
   Audit what already exists before recommending new objects. Keep old layouts,
   static constructor facts, actual native runs and current rendered observations
   separate. Never treat historical source acceptance as a current whole-map pass.
2. Inventory the complete useful feature envelope: support terrain, vertical
   foundations, cap overhangs, hidden native bearing cylinders, side roll-ins,
   elevated landings, awnings, posts, retaining backs, guides, query patches,
   audio, encounter markers, cameras and map/route records. A guide or mesh
   centre is not the physical edge. Inspect compound native integer shape IDs.
3. Trace protected human tasks: score/combo branches, ten career goals, ordered
   encounter gates, recording/collectible access, easier routes and district
   mouths. Preserve their actual meaning. A centreline test is not a 4m riding
   corridor or a 3m landing certificate. Distinguish legacy grounded-yaw route
   feasibility from mapped-steering circuit evidence.
4. For each suggested line name launch, useful capture/manual/air choices,
   landing, runout and same-rider re-entry. Ask what genuinely changes after a
   landing. Two relocated props, the reverse of one rectangle, a collection
   circuit or a route registry are not automatically a second returnable line.
   Compare the proposal with proving a useful existing line at lower topology
   risk. The retained benchmark is two distinct returnable lines per arena and
   three demonstrated cross-arena circuits, not an obstacle count.
5. Compute approach/runout widths, native/display bounds and prospective travel
   intervals honestly. Reference 8m/s calculations are design estimates;
   measured meaningful-event gaps require real physics steps and actual inputs.
   Charge inputs and decorative proximity do not count as new opportunities.
6. Treat enclosure as gameplay. Check which side of each finite face returns
   the rider, both directions, seam/corner misses, longest charged departure,
   supported shoulders and recovery behind the edge. Keep scenery boundaries
   visible and native. Do not infer containment from height alone, delete
   supported recovery terrain, add invisible catches or exclude whole owner RIDs.
7. Inspect construction code before claiming budget neutrality. Resample every
   polyline leg explicitly when native segment identities/counts matter. Equal
   total length does not imply equal shape, post or draw counts. A new ArrayMesh
   can increase unique meshes while replacing primitive instances; account for
   startup mesh interning, materials, texture memory, visibility and actual cost.
   Exact flat orthogonal box panels may reuse shared primitives if native faces
   and world material scale agree; grade/corner cases need their own proof.
8. Recommend the smallest coherent revision and enumerate adversarial tests.
   Keep loaded support separate from unloaded clearance: reuse authenticated
   current native contracts, not new tolerances. A real displayed board/tyre or
   shoe overlap cannot be excused by a loaded capsule margin. Public legacy guide
   metadata alone cannot certify named truck bearing or prevent hovering.
9. Deliver source observations, explicit inferences, rejected options, exact
   hashes, guarded next action and open native/render/cost/human gates. Do not
   self-certify production work. Read-only review can be completed while shared
   source is frozen; native execution requires the root's explicit schedule.

When findings uncover a new production defect, preserve exact reproduction
state, component/frame, finite shape owner/ID and actual query result before
suggesting a repair. Bounded failure logs need a first sample of each query
class so repeated capsule contacts cannot hide a later model collision.
