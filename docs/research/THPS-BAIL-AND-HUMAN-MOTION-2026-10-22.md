# Bail recovery and believable skater movement

22 October 2026. Owner-requested investigation, based on production `83758c3`. Research and a reproducible native diagnosis are complete. Recovery and character changes described below are **proposals, not implemented fixes**. This becomes the next implementation focus ahead of park construction; the existing map/performance requirements remain.

## What ours does now

`skater.gd` emits `bailed` and immediately calls `reset_skater()` for manual/lip imbalance, failed rail travel or clearance, blocked transition detachment, and out-of-world recovery. `recover_to()` emits the same event and immediately resets at a local hazard destination while preserving the run's restart spawn. Main drops the pending combo and fails encounters at that signal. There is no falling/sliding/getting-up state. Ordinary landings are intentionally forgiving; this investigation does not authorize silently adding punitive landing rules.

The actual native input audit on Apple M5, Godot4.6.3, Compatibility, balanced1280×800 records **1,061 physics samples** and24 captured frames, with12 selected original PNGs retained. Its3/0 result certifies completion of the diagnostic, not acceptable animation. [Evidence and reproduction](../testing/bail-recovery/README.md).

A real uncorrected manual loses balance once. Tick1641 is at`(-22,0.000026,4.856507)` moving5.301507m/s; tick1642 is at`(-22,0.8,28)` with zero velocity. That is **23.157315m in one physics tick**, with no visible fall, slide or get-up. The nominal floor flag is still true at the elevated reset origin in that observation. This is a measured missing recovery sequence, not a hypothetical visual complaint.

The limb audit reads actual skeleton joint origins and hand/foot markers, divided by the authored segment lengths (thigh0.43m, calf0.41m, upper arm0.30m, forearm0.29m). It finds:

| Actual phase | Largest measured extension | Observation |
|---|---:|---|
| Push | calf1.27580× / **+27.58%** | Ground-reaching rear foot exceeds leg reach. |
| Brake | calf1.24396× / **+24.40%** | Dragging foot has the same constraint problem. |
| Manual/bail trial | calf1.28158× / **+28.16%** | Includes entry/exit transitions; not attributed solely to the held manual. |
| Melon grab | forearm1.18760× / **+18.76%** | Includes entry/exit; held pose alone is not the complete fault. |
| Nose grab | forearm1.07790× / **+7.79%** | Board-reaching arm exceeds its authored reach. |
| Tail grab | forearm1.01112× / **+1.11%** | Smaller overreach. |
| Idle, charged jump, Indy and method trials | ~1.00000× | No material overextension in these sampled trials; not all-angle acceptance. |

`SkaterVisual._joint()` clamps the distance used to calculate the middle joint, but the original extremity target is still used by `pose_leg/pose_arm`. `SkaterGarments._pose_segment()` then scales a bone to the resulting distance. An unreachable endpoint consequently lengthens the lower segment. This is a concrete contributor to rubbery limbs. Simply clamping the hand or foot would lose board/ground contact: hips, torso and contact targets need a coordinated reachable pose. Root inspection of chase and close profile frames also leaves weight transfer, abrupt state transitions, hand relaxation and overall human silhouette open. Segment lengths alone cannot certify believable movement.

R03 should separate a `begin_bail` event from eventual recovery. Entry snapshots context, stops manual/rail/lip/transition tricks and flushes requests; subsequent ticks must not repeatedly emit failure. Main's water query must not retrigger a pending hazard bail each tick. Timer/encounter handling must remain authoritative while recovering; pause freezes progress, explicit Restart cancels it immediately, and held inputs require a fresh eligible request on resumption. Check supported upright capsule clearance before standing, rather than ignoring a low ceiling or nearby wall. A bounded fallback must use verified safe support and preserve the run's restart spawn. Proposed phase timings must be tuned locally and labelled as such; no original frame count has been translated into seconds here.

Use the existing Skeleton3D/Skin, authored pose targets and CharacterBody3D collision for the first sequence. Unconstrained ragdoll simulation is not needed to establish these behaviours and could add unstable contact, camera and performance work. Evaluate native physical bones only if a bounded visual/physics prototype later demonstrates a benefit. Do not copy reconstructed code or source-game animation curves. A separately moving board can first reuse its current mesh/transform; any added physical body needs a declared cost and collision/return test.

Budget before implementation: **zero additional production draw surfaces, triangles, textures, materials, lights or skin bones** for the first pose/recovery pass; no per-frame mesh construction. Declare and measure added pose/collision CPU work. Native admission retains the existing strict frame envelope and≤1.05×worse matched control, with every long frame disclosed. The current stutter issue remains open; do not expand the map to hide it. If a candidate fails timing, contact or framing, retain it as rejected evidence.

This investigation does not close M05-002/M05-006, M06-003/M06-007, human likeness/fun, current-map stutter, target-controller/export or the outstanding park/world/UI work. It identifies a narrower first fix that can be evaluated before spending effort on replacement character assets.
