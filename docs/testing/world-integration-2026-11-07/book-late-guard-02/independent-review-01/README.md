# Independent private Book review

The final private Catalog/LevelCareerBook has no remaining source or recorded-native blocker to guarded integration. This review made **40 offline checks**, all passing; it did not launch Godot or modify an actual profile. The [machine-readable review](independent-review.json) and [exact audit script](independent-audit.py.txt) record the checks.

The corrected Book passes the recorded **65/0** native cohort. The original save guard, changed only from a static method to an instance method so the same deterministic fault fixture can run, produces **59/6**. All original 56 checks pass in both. Each of three late-file cases starts with a valid primary and an existing healthy backup; the corrected writer refuses a newly introduced future or corrupt `.bak.tmp`, or a foreign valid `.tmp` with different completed goals and scores, while retaining those bytes. The old guard fails both refusal and preservation checks for each case.

The source change is confined to `save_profile`, `_write_verified`, and a new `_guard_save_family`. It authenticates the exact serialized own candidate, compares the expected signatures of all four slots before the backup copy and each rename, and verifies that a copied backup matches the original primary. This addresses the observed overwrite defect. These are optimistic conflict checks, not an interprocess lock or proof of complete filesystem race freedom.

Both native projects have **nine** source inputs, with identical before/after maps. The preserved Book, Catalog and adversarial tests match those maps; the retained baseline progression/core/launcher dependencies also match the actual frozen source at review time. The outer Python launcher was preserved after execution and was **not bound before execution**. That limitation is retained; no stronger launcher identity is inferred. The negative cohort's six explicit `ERROR: FAIL:` lines and exit 1 are expected counterexample results, not a clean positive execution.

Catalog metadata and namespaced Merchant goals are separate from the unchanged City Tour progression domain. Migration requires all four new save slots to be absent; protected old paths and corrupt/future/recovery candidates are retained. World paths in the Catalog are strings: this code-only fixture does not instantiate Main, a world, HUD or Music. Selected-world loading, actual profile migration, Main event/label consumers, input cancellation, full regression, playability and Mac filesystem behaviour remain integration gates. Custom isolated callers must explicitly disable the default legacy fallback.
