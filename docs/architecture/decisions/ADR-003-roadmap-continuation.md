# ADR-003: Complete the truncated roadmap without reducing release scope

Status: Accepted as a planning baseline; individual feature details remain tunable. Date: 17 October 2026. Owner: A01/A02.

## Context

The supplied document defines the full first release and says there are eight milestones, but the pasted source ends after the M03 Glasgow grey-box description. The user asks for full tasks so work can resume after credits run out.

## Decision

Preserve the original source unchanged. Keep M00 foundation, M01 skating proof, M02 combos and M03 Glasgow grey-box aligned with the source. Propose M04 missions/progression, M05 art/audio/NPCs, M06 UX/hardware/performance and M07 release as a transparent continuation derived from the full Release 1 requirements. Every requirement maps to tickets and tests. Human playtests remain exit gates.

## Alternatives

Stopping the backlog at M03 would omit clearly requested release systems. Pretending the missing milestone names came from the user would misstate the source. Dropping costly voice or macOS release requirements would silently change product scope.

## Consequences

The backlog is complete enough for continuity while distinguishing authored planning from supplied source. Later agents can reorder independent tasks with recorded rationale, but cannot omit mechanics, goals, voiced reactions, target hardware or release validation without an explicit owner-approved change.
